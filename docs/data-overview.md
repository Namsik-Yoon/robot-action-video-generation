# 초기 데이터 분석

분석일: 2026-10-07. 출처: 사용자가 공식 다운로드한 `open.zip`.
ZIP 크기 9,209,529,683 bytes, 압축 해제 파일 합계 9,290,445,710 bytes.
이전 단계에서 전체 ZIP CRC 검사를 통과했고, 이번 단계에서 안전한 경로 확인 후 전체 압축 해제를 완료했습니다.

## 무엇이 있는가

- `data/train/`: LeRobot v2.1 형식의 로봇 조작 데이터 128묶음. 폴더별 `meta/info.json`, `meta/episodes.jsonl`, 프레임 단위 Parquet와 에피소드별 MP4가 있습니다.
- 학습: 에피소드 11,132개, Parquet 11,132개, 영상 11,132개. 메타데이터 기준 총 1,025,666프레임.
- 로봇 종류: so100 125묶음, so100-blue 2묶음, so100-red 1묶음.
- 조작 종류: 폴더명 기준 물체 집기·옮기기, 정렬, 쌓기, 배터리·블록·공·컵 등을 다루는 다양한 환경. 실제 성공 여부나 전체 작업 의미는 아직 영상으로 검증하지 않았습니다.
- `data/eval/`: RGB 초기 이미지 216개와 행동 배열 216개. 모든 sample ID가 일치합니다.
- `baseline/`: 공식 예제 노트북, 모델 코드 및 제공 checkpoint. 실행하지 않았습니다.
- `submission_kit/`: 생성 MP4를 CSV로 변환하는 공식 코드, action extractor checkpoint, sample submission. 수정하거나 실행하지 않았습니다.

## 입력을 어떻게 읽는가

평가 이미지 216개 모두 640×480 RGB입니다. 행동 배열은 모두 float32 `(16, 6)`이고 NaN/Inf는 없습니다.
즉 한 샘플은 초기 이미지 1장과, 16개 시점에 대한 6차원 로봇 행동 조건으로 구성됩니다.
행동은 shoulder pan/lift, elbow flex, wrist flex/roll, gripper 항목으로 설명됩니다.
정확한 물리 단위와 생성 영상의 시간 규약은 데이터 로더·공식 예제를 읽고 확정해야 합니다.

학습 Parquet의 공통 컬럼은 `action`, `observation.state`, `timestamp`, `frame_index`, `episode_index`, `index`, `task_index`입니다.
action과 state는 6차원 실수 배열입니다. 영상은 Parquet 안에 픽셀로 들어 있지 않고 별도 MP4로 저장됩니다.
데이터셋별 첫 Parquet 스키마 검사에서 126묶음은 공통 컬럼만, 1묶음은 `next.reward`/`next.done`, 1묶음은 `grid_position`도 포함했습니다.

## 데이터 로더 설계에 영향을 주는 차이

- FPS: 메타데이터 기준 127묶음은 6 FPS, 1묶음은 10 FPS. 일괄 6 FPS 가정은 피해야 합니다.
- 영상 해상도: 메타데이터 기준 640×480 123묶음, 1280×720 2묶음, 1920×1080 3묶음. 크기 정규화 정책이 필요합니다.
- 코덱: 메타데이터 기준 AV1 81묶음, H.264 47묶음. 두 코덱을 지원하는 디코더가 필요합니다.
- 영상 feature key: `observation.images.image` 127묶음, `observation.images.s_left` 1묶음. 경로를 하드코딩하면 일부를 놓칩니다.
- 에피소드 길이: 최소 1, 중앙값 80, 95백분위 165.45, 최대 1,072프레임. 16프레임 미만 34개. 패딩·제외·샘플링 기준을 먼저 결정해야 합니다.
- 폴더별 Parquet와 영상 episode stem 집합의 불일치는 발견되지 않았습니다. 다만 모든 MP4를 디코딩해 프레임 수를 대조한 것은 아닙니다.

## 검증 범위와 남은 일

전체 메타데이터, 파일 짝, 평가 이미지 디코딩 검증, 평가 배열의 형식·유한값을 점검했습니다.
학습 Parquet는 데이터셋당 첫 스키마와 한 샘플 내용만 읽었습니다. 전체 학습 수치의 결측·범위, 실제 영상 디코딩, 영상과 timestamp 정렬은 미검증입니다.
개별 원본 샘플과 전체 inventory는 `reports/local/`에만 저장하고 게시하지 않습니다.

학습/검증은 같은 에피소드의 프레임이 섞이지 않도록 분리하고, 필요하면 데이터 수집 폴더를 기준으로 더 엄격하게 나눕니다.
정규화 통계는 학습 분할에서만 계산합니다. 평가 입력은 학습이나 검증에 재사용하지 않습니다.
다음 단계는 전체 모델 학습이 아니라 **에피소드 하나의 영상과 행동을 같이 읽는 데이터 로더 검증**입니다.
